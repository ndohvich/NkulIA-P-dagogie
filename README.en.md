## The problem

Cameroonian teachers already have official reference documents in
their school (progression sheets, pedagogical plans) that precisely
describe the curriculum. Today they manually rewrite these into
lessons, worksheets and assessments — repetitive, time-consuming, and
with no automatic guarantee that what's assessed matches what was
actually taught.

## What NkulIA does

NkulIA imports existing pedagogical documents, understands their
hierarchical structure, and generates lessons, problem statements,
exercises and assessments — with **every piece of generated content
explicitly labelled by provenance**:

| Label | Meaning |
|---|---|
| 🟢 Reference | Taken as-is from the imported document |
| 🔵 Deduction | Inferred from several elements of the reference material |
| 🟡 AI recommendation | Generated by the model, no direct source |
| ⚪ Missing information | Absent from the reference material — never fabricated |

The teacher stays the final decision-maker: nothing is exported as a
final PDF without explicit human validation.

## Engineering highlights

This is a solo, offline-first desktop project — the engineering
choices below were made deliberately for that context, not by default
(see [`docs/adr/`](docs/adr/) for the full reasoning and the
alternatives that were explicitly rejected, including Postgres/Redis/
Celery and a cloud deployment pipeline, and *why*):

- **Architecture Decision Records** for every structural choice, not just a README claim
- **Local-first data model**: SQLite + SQLAlchemy + Alembic migrations, no server dependency
- **Explicit anti-hallucination contract**: a 4-state provenance model enforced at the API boundary, not just a prompt instruction
- **Desktop-appropriate CI/CD**: lint + test on every PR, PyInstaller build attached to GitHub Releases on semantic version tags — no Docker registry or cloud deploy pretending to exist for an app with no server
- Conventional Commits, Semantic Versioning, ADRs, and a documented issue/PR backlog (see [`docs/ISSUES.md`](docs/ISSUES.md), [`docs/PULL_REQUESTS.md`](docs/PULL_REQUESTS.md))

## Architecture

```
┌─────────────────────────────────────────────┐
│  PyWebView window (native Windows shell)     │
│  ┌─────────────────────────────────────────┐ │
│  │  React + Vite + Tailwind frontend        │ │
│  └─────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────┐ │
│  │  FastAPI backend (same process)          │ │
│  │  ├── Local auth (Argon2)                 │ │
│  │  ├── Import & structuring (RAG)          │ │
│  │  ├── Generation (LLM + provenance)       │ │
│  │  └── PDF export                          │ │
│  └─────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────┐ │
│  │  Local SQLite (SQLAlchemy + Alembic)     │ │
│  └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

## Tech stack

| Layer | Choice |
|---|---|
| Native window shell | PyWebView |
| Frontend | React + Vite + Tailwind CSS |
| Backend / API | FastAPI (Python) |
| Database | SQLite (SQLAlchemy + Alembic) |
| Pedagogical retrieval | Embedded RAG, no external server |
| Windows packaging | PyInstaller |

## Local development

```bash
git clone https://github.com/ndohvich/NkulIA-Pedagogie.git
cd NkulIA-Pedagogie

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e "./backend[dev]"

cd frontend && npm install && cd ..

python desktop/main.py
```

See [`CONTRIBUTING.md`](CONTRIBUTING.md) for lint/test commands and
branching conventions.
